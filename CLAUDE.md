# Besa Goods — besagoods.com

Static site, no framework, no package.json. HTML pages with page-specific
inline CSS/JS plus two shared files in `assets/`. Hosted on GitHub Pages.

**One build step:** the multilingual pages are edited in `_src/` and turned
into per-language pages by `python3 _tools/build.py` (no dependencies). Never
edit `index.html`, `essentials.html`, `privacy.html`, `de/…` or `sq/…` by hand:
they carry a "Generated by _tools/build.py" comment and are overwritten. Edit
the source, rebuild, commit source and output together.

Sells Albanian mountain tea (Çaj Mali) on a **request-first** basis and
recommends teaware / Albanian coffee accessories through Amazon affiliate
links. Audience: Albanian diaspora and tourists, mainly UK and Germany.
Business base: Madrid.

## Rules for working here

- **`main` deploys live** (GitHub Pages, branch `main`, path `/`). Never commit to
  `main` directly; work on a branch and merge via PR.
- Never commit secrets. The Stripe `pk_live_…` publishable key and the Formspree
  form ID in the HTML are public by design; secret keys (`sk_…`, webhook
  secrets, API tokens) must never appear in this repo.
- Do not change prices, product claims, shipping terms or availability wording
  without the owner's approval. Do not add social-proof numbers, ratings or
  testimonials that are not real.
- Keep the visual design: tokens in `assets/besa.css` `:root`, Poppins, the
  forest-green / bark / gold palette.
- Every user-facing string needs EN, SQ and DE versions.

## Visual style: heritage with crystal accents

- Base palette unchanged (cream, parchment, forest, bark, earth, gold). Crystal
  tints added as tokens in `assets/besa.css`: `--ice`, `--teal`, `--amethyst`,
  `--gold-pale`, plus `--prism` (hairlines, borders) and `--prism-soft` (card
  borders). Cut-corner shape `--facet`, diamond `--diamond`.
- Background details are inline SVG data URIs: `--folk` (kilim lattice on
  light sections), `--folk-gold` (on forest sections), `--zigzag` (footer edge).
- Type: Cormorant Garamond 700 + 600 italic for headings, logo, prices-as-
  display numbers; Poppins 300/500/600 for everything else. Only those 5 font
  files are requested; don't add weights without checking page weight.
  `body` uses lining numerals.
- Motion: hover shine on product cards (text area only, never over photos),
  card lift. All motion is disabled under `prefers-reduced-motion`.
- Every page's inline `<style>` ends with a "Heritage + crystal look" block that
  overrides that page's original rules; shared parts live in `besa.css`.
- Contrast: all text pairs were checked at WCAG AA (including over the lattice
  and translucent panels). `--light` and `--teal` were darkened for this; keep
  small text on `--muted` or darker.

## Languages (EN / SQ / DE)

- Sources in `_src/` hold every string three times as sibling elements with
  class `en`, `sq`, `de`. `_tools/build.py` keeps only one language per output
  page and bakes `data-t-*` (title, `<option>` text), `data-content-*` (meta
  description), `data-ph-*` (placeholders), `data-alt-*` and `data-al-*`
  into the page. It refuses to build if two pages share a title.
- URLs: English at `/…` (x-default), German at `/de/…`, Albanian at `/sq/…`.
  Each page has a self canonical, hreflang en/de/sq + x-default, og:locale.
  The EN/SQ/DE buttons are links between the versions; clicking one stores the
  choice in `localStorage['besa_lang']`.
- English pages redirect old `?lang=sq|de` URLs, and visitors who picked a
  language before, to `/sq/` or `/de/` (crawlers only see the `?lang` one).
- Swiss German: not a separate variant. If one is added later, give it its own
  folder and `de-CH` hreflang in `build.py`.
- Links inside sources use root paths for assets (`/assets/`, `/images/`) and
  relative paths for pages (`essentials.html`, `./#request`) so they resolve
  inside `/de/` and `/sq/`.
- `besa.js` still supports runtime switching (`[data-set-lang]`, `data-*-xx`)
  for any page that keeps all languages, but all built pages are
  `data-fixed-lang`.

## Tea request flow (no stock, no payment up front)

1. Visitor fills `#request-form` on the home page (`/`, `/de/`, `/sq/`): name, email, country, tea,
   quantity, reply language, notes, required GDPR consent checkbox.
2. JS posts it as FormData to Formspree (`action` on the form; currently the
   existing contact form ID `xpwzgjgv`) with a `_subject` like
   `Tea request: 3 × Caj Mali 50 g – Name (Country)`, sets
   `sessionStorage.besa_request_sent`, and redirects to the request thank-you
   page in the current language.
3. The owner replies by email with price + shipping, then sends a Stripe
   payment link. Payment completes the purchase; delivery up to 5 days after.
- The Stripe Buy Button markup is kept in `<template id="stripe-checkout">`
  inside `#request`: inert, not rendered, script not loaded. Move its contents
  out of the template to re-enable direct checkout.

## Amazon affiliate products

- 7 products (3 teapots, cezve, grinder, cups, tray), each an `amzn.to/…` link
  with `target="_blank" rel="sponsored nofollow noopener"`, on the home shop
  grid (`data-cat` for filters) and the essentials page, in every language.
- Audit (Nov 2026): all 7 short links resolve to **amazon.com** (US store)
  with tag `besagoods-20`; none missing, none different.
- Visible disclosure right above the products ("As an Amazon Associate I earn
  from qualifying purchases.", EN/SQ/DE), longer note under them, and in every
  footer.
- Clicks fire `amazon_click` {product_name (English), language, link_url} via
  gtag and Meta `trackCustom('AmazonClick')`, only after cookie consent
  (`besa.trackAmazonClick` in `besa.js`).
- Prices are hard-coded and labelled indicative. No Amazon star ratings, review
  counts or sales figures (Amazon Associates rules).

## Analytics, tags and consent

- Nothing from Google Ads or Meta loads until the visitor clicks **Accept** in
  the cookie banner (`besa.js`). Choice stored in `localStorage['besa_consent']`;
  "Cookie settings" buttons (`[data-cookie-settings]`) reopen the banner;
  Reject after Accept sends a consent `denied` update.
- On accept: `gtag.js` for **`AW-18368007697`**, plus any IDs in
  `CONFIG.extraGoogleTagIds` (e.g. `GT-5R4G63DN`, not added yet), plus the Meta
  pixel if `CONFIG.metaPixelId` is set.
- **Lead** (request thank-you pages): `generate_lead` always; Google Ads
  conversion if `CONFIG.adsLeadLabel` is set; Meta `Lead` if the pixel is set.
  Fires only after a real submission (sessionStorage flag) and with consent.
- **Purchase** (`thank-you*.html`): unchanged, still loads gtag directly and
  uses the placeholder label `YOUR_CONVERSION_LABEL`.
- No Google Tag Manager container is used.

## Deployment

GitHub Pages, legacy build (no Actions workflow), source `main` / root. Custom
domain `besagoods.com` via `CNAME`; `www` 301-redirects to the apex, so all
canonical/hreflang/sitemap URLs use `https://besagoods.com`. Pushing to `main`
publishes within a minute or two.

Local preview: `python3 _tools/build.py`, then `python3 -m http.server 4180`
in the repo root and open `http://localhost:4180/` (or `/de/`, `/sq/`). Use
`.html` names locally; only Pages maps `/essentials` to `essentials.html`.
After deploying, resubmit `https://besagoods.com/sitemap.xml` in Google Search
Console and Bing Webmaster Tools.
